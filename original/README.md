# NetUtil — диагностика сетевых конфигураций Windows 11

Утилита для поиска причин, по которым после работы VPN-обходчиков
(Amnezia WG, VLESS, sing-box, xray, Hiddify/Happ, Hysteria, tun2socks и т.п.)
всё «отваливается» и тормозит. Проверяет **все** сетевые настройки Windows
и на главном экране в режиме онлайн показывает, что реально доступно.

Два интерфейса:

- **`netutil_qt.py`** — красивый Material-интерфейс (PySide6) —
  **рекомендуется**;
- **`netutil.py`** — консоль/Tkinter, только стандартная библиотека
  (без установки зависимостей).

## Установка

```bat
pip install -r requirements.txt
```

## Запуск

```bat
:: Красивый интерфейс (Qt)
python netutil_qt.py

:: Tkinter-интерфейс (без зависимостей)
python netutil.py

:: Только текст в консоль
python netutil.py --cli

:: Сохранить снимок конфигурации в JSON (без GUI)
python netutil.py --export report.json
```

Требуется Python 3.8+. **Запускай от администратора** — иначе часть данных
недоступна (DNS-кэш, список процессов, часть правил брандмауэра).

## Главный экран

Это набор живых карточек — открыл и сразу видно состояние:

- **Сводный вердикт** сверху: ✅ **ВСЁ ОК** / ⚠️ **ЕСТЬ ЗАМЕЧАНИЯ** /
  ❌ **НЕ ОК**, а под ним — расшифровка, что именно не так. Рядом —
  карточка **📡 Мониторинг** с живым процессом фоновой проверки
  (последняя проверка, обратный отсчёт до следующей, Включить/Пауза).
- **Доступность по зонам** (флаги рисуются как иконки), для каждой — статус,
  IP с флагом страны, **пинг, DNS, скорость, число доступных сайтов**,
  прогресс-бар и спарклайны истории пинга и скорости с подписями:
  - **RU** — отечественные (Яндекс, VK, Госуслуги, Сбербанк, Ozon…);
  - **Зарубежные** — незаблокированные (Microsoft, GitHub, OpenAI, Netflix…);
  - **Заблокированные** — под блокировкой (Instagram, X, YouTube, Discord…).
- **🔒 VPN и маршрутизация** — туннель, режим, split-tunneling, качество,
  диагноз.
- **🌍 IP-адреса** — какой IP видят сайты в РФ, «наружу» и для заблокированных.
- **🧭 DNS** — резолвинг, резолвер (с флагом страны), **split-DNS**,
  фильтрация, кэш. Карточка видна всегда; в сводку ОК/НЕ ОК OK-пункты DNS
  не попадают, чтобы не шуметь (проблемы показываются).
- **⚙️ Система** — системный прокси и виртуальные адаптеры (Winsock/LSP —
  в подменю «Система», на главной не показывается, если всё ок).
- **🎮 UDP (игры)** — качество UDP: **RTT и потери**. Методы одинаковые
  для RU и зарубежных — STUN (3478), NTP (123), DNS (53); отличаются
  только адреса. Отдельной зоны «Заблокированные» нет: **UDP в РФ не
  блокируется** (блокировка на уровне TCP/SNI), а QUIC конфликтует
  с Xray. Потери **больше 25% — красным**. Полезно для игр
  (Elite: Dangerous и др.), где UDP — основной транспорт.

Зона считается **доступной**, если ответило **>= 80%** её сайтов.
Пинг — среднее с **отсевом выбросов** (IQR): медленные SYN-ACK отдельных
серверов не задирают показатель. **DNS** — среднее время резолва доменов
зоны. Проверка идёт **по 3–4 параллельных запроса** — чтобы не создавать
всплеск и не триггерить VPN/DNS/CDN.

**Проверка split-DNS**: утилита берёт DNS-серверы прямого и туннельного путей
и опрашивает их напрямую (raw UDP) доменом `whoami.akamai.net` — тот
возвращает IP самого резолвера. Если пути идут через разные резолверы
(и страны различаются), split-DNS работает.

**Диагноз VPN** по доступности зон (строка «Диагноз» в карточке VPN):

- заблокированные открылись меньше чем наполовину, а туннель **не** поднят →
  «VPN выключен» (это ожидаемо);
- туннель поднят, но **RU** и обычные зарубежные тоже упали → «VPN откис,
  меняй локацию/провайдера»;
- туннель поднят, зарубежные работают, а **RU** нет → проблема
  **split-tunneling**;
- туннель поднят, RU в порядке, а **обычные зарубежные** нет → VPN не
  пропускает зарубеж;
- всё открыто, кроме **заблокированных** → VPN не обходит блокировки.

## Что проверяет (вкладки)

| Вкладка | Что показывает |
|---|---|
| **Главная** | Карточки: вердикт, зоны, VPN, IP, DNS, система |
| **Сводка** | Находки карточками (❌/⚠️/ℹ️) + подсказки |
| **Система** | Подменю: Онлайн (по сайтам), Адаптеры, DNS, Маршруты/MTU, Прокси, hosts, Процессы/Службы, Брандмауэр, Порты, Winsock/TCP |

## Списки сайтов (редактируемые)

- По умолчанию **по 25 доменов** в каждой зоне (RU / Зарубежные /
  Заблокированные).
- Кнопка **📋 Списки** в шапке открывает редактор: по вкладке на зону,
  один URL на строку, «Сбросить к дефолтным».
- Списки сохраняются в **`sites.json`** рядом с утилитой и читаются при
  старте; после сохранения проверка запускается заново.

## Ход проверки

Всё про проверку — **в карточке ОК / НЕ ОК**, отдельной карточки нет:

- пока идёт: `ИДЁТ ПРОВЕРКА` + прогресс-бар + `Сайты: 56 / 76` и счётчики
  по зонам (`RU 24/26 · Зарубежные 24/25 · Заблокированные 6/25`);
- по завершении: `✅ Проверка завершена в 13:49:12 · 76/76 сайтов`,
  ниже — список статусов с цветными точками.

Карточка **📡 Мониторинг туннеля** показывает, **что именно** проверяет
периодическая проверка и с каким результатом — списком с цветными точками:
`VPN: активен`, `DNS: 23 мс`, `Пинг: 18 мс`, `Скорость: не мерили (пауза)`.
Если VPN выключен, дублирования нет — статус показан один раз.

## Резидентный режим: трей и умный мониторинг

- Иконка в **системном трее** с цветовым статусом (серый/зелёный/жёлтый/красный)
  и тултипом; меню «Открыть / Выйти». Крестик **сворачивает в трей**.
- **Уведомления** в центре уведомлений при нестабильном туннеле.
- **Умный мониторинг** (чекбокс, раз в 60 с) с минимальной нагрузкой на канал:
  1. лёгкая проверка — VPN активен? и **реальный HTTPS через текущий путь**
     (DNS → TCP → TLS → HTTP), а не закэшированный `getaddrinfo` или один
     TCP-коннект к fake-ip (иначе ложное «всё ок»);
  2. всё ок → скорость **не меряем** (почти ноль трафика);
  3. сомнения (нет ответа / трафик очень медленный) → меряем скорость
     (не чаще раза в 5 минут);
  4. скорость упала < 5 Мбит/с → уведомление «туннелю плохо».
  VPN выключен → уведомлений нет.
- Если VPN **включили** (мониторинг заметил переход «выключен → активен»),
  полная проверка запускается автоматически.

## Оформление

- Тёмная/светлая Material-тема, тени под карточками, градиент сводной
  карточки, эмодзи-иконки.
- **Флаги стран рисуются как иконки** (QPixmap), а не эмодзи — на Windows
  эмодзи-флаги не отображаются, поэтому используется своя отрисовка.
- **🎨** в шапке — переключение акцентного цвета (6 палитр).
- **🌓** в шапке — переключение тёмной / светлой темы.
- Спарклайны истории пинга и скорости с подписями и диапазоном.
- Тултипы на карточках и значениях, плавное появление окна.
- Вся информативность сохранена: полная системная диагностика — в подменю
  **Система**.

## Что делает `ipconfig /flushdns` и `netsh winsock reset`

Утилита анализирует ровно то, с чем работают эти команды, чтобы ты понимал,
что именно чинится:

- **`ipconfig /flushdns`** — очищает **кэш DNS-резолвера** (служба DNS Client).
  Утилита показывает этот кэш (вкладка DNS) и подсвечивает записи, которые
  резолвятся в подозрительные адреса (loopback/частные/0.0.0.0) — признак
  подмены или «зависшей» записи. Сброс заставляет Windows заново запросить
  имена у DNS-серверов. Он **не меняет** DNS-серверы и **не чинит** маршруты.

- **`netsh winsock reset`** — возвращает **каталог Winsock (LSP)** к стандартному
  набору провайдеров Microsoft, удаляя сторонние LSP, оставленные VPN/прокси-
  программами. Утилита показывает сводку каталога (сколько базовых провайдеров,
  сколько сторонних) и список сторонних. Если каталог битый, сокеты не
  создаются/не резолвятся. После сброса нужна перезагрузка. Часто идёт в паре
  с `netsh int ip reset` (чинит стек TCP/IP, а не Winsock).

## Частые причины и лечение

- **Маршрут по умолчанию уходит в туннель** (ERROR): после «отключения» VPN
  остаётся маршрут `0.0.0.0/0` через туннельный интерфейс с низкой метрикой —
  весь трафик идёт в мёртвый туннель.
  → Подними метрику туннельного адаптера (TCP/IPv4 → Дополнительно → снять
    «Автоматическое назначение метрики», поставить большое значение) или удали
    адаптер.

- **Остаточные TUN/TAP/WireGuard-адаптеры** (AmneziaVPN, WireSock, tun2…):
  → Удалить в «Диспетчере устройств» (Вид → показать скрытые).

- **Сломанный Winsock / стек IP**:
  ```bat
  netsh winsock reset
  netsh int ip reset
  :: затем перезагрузка
  ```

- **DNS-кэш / подмена**:
  ```bat
  ipconfig /flushdns
  ```

- **Остаточный системный прокси** (127.0.0.1:порт на выключенный xray/sing-box):
  Параметры → Сеть и интернет → Прокси → выключить.

- **MTU** при обрывах/тормозах: попробуй 1400–1420 на туннельном адаптере:
  ```bat
  netsh interface ipv4 show subinterfaces
  netsh interface ipv4 set subinterface "ИмяАдаптера" mtu=1400 store=persistent
  ```

## Сохранение снимка

Когда проблема повторится, запусти `python netutil.py --export report.json`
(или кнопка «Сохранить отчёт…» в GUI) — файл содержит все секции, находки и
результаты онлайн-проверки, его удобно переслать для разбора.
